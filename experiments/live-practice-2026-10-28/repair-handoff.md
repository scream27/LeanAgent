# 수리 에이전트 연결: 이번 실험에서 확인된 입력과 경계

## 먼저 읽을 파일

- `repair-cases.jsonl`: 실제 거절된 후보 13건. `case_id`, 원본 `statement`, `original`, `failed_candidate`, 구조화된 `feedback`, 전체 `logs`, 문맥 템플릿과 환경 manifest 경로, 실패 직후 incumbent를 포함한다.
- `failure-routing.json`: 위 13건을 evaluator의 error.kind로 분류한다. compile 10건, timeout 3건. 이 분류에는 LLM이 필요 없다.
- `selections.json`: 기본 하네스의 고유 29문제 결과. 원본 단계에서 차단된 문제에는 검증된 선택 증명이나 점수를 만들어 넣지 않는다.
- `retry-selected-proofs.json`: timeout 사후 재시도 후 재선택한 P15/P19 증명. 기본 실행을 덮어쓰지 않은 별도 결과다.
- `manifest.json`: 원시 35행과 고유 문제의 대응 및 입력 해시.

파일 내부 경로는 이 저장소에서 실행한 환경을 가리킨다. 대용량 생성 환경 일부는 순차 정리했으므로 다른 머신에서는 지정 revision·Lean 버전으로 재구축해야 한다. 보관된 컴파일 로그를 재생하는 것은 새 Lean 검증이 아니다.

## 최소 연결 계약

1. 대상 statement·context·imports·revision을 고정한다. 수리기는 proof body만 반환한다. 새 공리, `sorry`, 명제 변경으로 실패를 우회하지 않는다.
2. 원본 검증 실패는 일반적인 후보 수리 큐와 분리한다. 데이터 경계 오류, 입력 검사 오탐, 공리 검사 오탐, 실제 sorryAx 의존성은 각각 다른 처리가 필요하다.
3. `timeout`이면 먼저 같은 코드와 환경에서 제한된 재시도 1회. 코드 해시·환경 fingerprint를 일치시키고, 원래 실패와 재시도 결과를 각각 보관한다. 이번 사후 진단에서는 새 프로세스 3회 측정을 동일한 180초 명령 제한으로 수행했다.
4. `compile`이면 첫 오류 및 goal과 원본 대비 변경 구간을 함께 제공한다. 오류 줄이 원인 줄이라는 보장은 없다. P5의 앞선 field_simp 제거가 뒤 conv 경로를 깨뜨리고, P23의 simp 병합이 이후 goal 처리에 영향을 줬다.
5. LLM 없는 후보 수리는 별도 실험으로 기록한다. 변경 구간 되돌리기, 탐색 tactic의 명시적 제안 채택, 불필요 단계 삭제 등을 사용할 수 있지만, 이번 실험에서 이 방법들의 자동 수리 성능을 측정한 것은 아니다.
6. 수정된 후보는 공용 verifier로 검증하고 원본 대비 공리 의존성을 검사한다. 컴파일 성공만으로 채택하지 않는다. 유효 후보끼리 공용 ranking으로 비교하고, 기존 best 및 원본 fallback을 유지한다.
7. 여러 버전이 지정됐다면 동일 후보를 추가 버전에서 검사한다. 버전마다 코드를 바꿔 통과한 결과를 한 증명의 robustness로 합산하지 않는다.

## 이번에 실제로 측정한 LLM 없는 개선

P15 후보2와 P19 후보2, P19 최종 선택 코드의 재시도가 모두 통과했다. 추가 LLM 호출과 proof 편집은 없었다. 공용 ranking으로 다시 선택하면 P15는 44.546점, P19는 53.604점이었다. 기본 선택 계측 대비 각각 +1.317, +20.023점이다. P19 기본 실행의 final_valid=false는 그대로 보존한다.

이 결과는 timeout과 논리 오류를 분리하는 정책의 가치에 대한 근거다. 반복 계측 변동이 포함되며, timeout 원인이 오직 자원 경합이라는 인과적 결론이나 모든 문제에 대한 일반적인 개선율은 아니다.

## Escalation에 넘길 때

실제 statement, 고정된 문맥, 실패 후보, 최초 오류/잔여 goal, 원본 대비 diff, 결정적 시도 및 결과, 마지막 verified incumbent를 함께 제공한다. 오류에 없는 가정을 보충하지 않는다. 자동 수리 예산 소진 시 프롬프트를 출력하되, 새 모델 호출은 별도 정책과 예산으로 센다.
